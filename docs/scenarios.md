# Проверяемые сценарии P0-01

Дата согласования правил: 26 ноября 2026 года.
Основание: [требования первой версии](requirements.md), раздел 5.
Это ожидаемые результаты для будущих тестов, не утверждение об их выполнении.
Они вводятся по мере реализации соответствующих задач учебного плана.

## 1. Общие условия

Все данные вымышлены. Денежные значения приведены в RUB. Каждый сценарий
начинается с отдельного подготовленного состояния. Операции выполняет вошедший
сотрудник, если прямо не проверяется отсутствие входа. Открытые клиентские счета
пассивные, учебная касса активная. Комиссий, процентов и овердрафта нет.
Слово «отказ» не означает откат уже подтверждённой операции.

До сбоя или отказа запоминаются оба остатка и журнал проведённых операций.
«Без движения» означает, что они не изменились; запись о попытке/отказе допустима.
Суммы и границы проверяются точной арифметикой.

## 2. Полная и неполная заявка

Контрольная дата обращения — **26.11.2026**, личное обращение совершеннолетнего
гражданина РФ за текущим рублёвым счётом для личных нужд.

| Реквизит | Синтетическое значение |
| --- | --- |
| ФИО | Тестов Алексей Учебнович |
| Гражданство | РФ |
| Дата рождения | 14.03.1992 |
| Вид документа | Внутренний паспорт РФ |
| Серия / номер | `9900` / `000001` |
| Дата выдачи | 15.03.2012 |
| Код подразделения | `000-000` |
| Наименование органа | Пусто, поскольку код заполнен |
| Адрес | г. Учебный, ул. Тестовая, д. 1, кв. 1 |
| ИНН | Отсутствует по условию синтетического примера; сотрудник фиксирует основание |

Нули в реквизитах — намеренные тестовые данные, не утверждение о существовании
такого паспорта или подразделения. Учебный подтверждающий документ содержит те же
данные. Проверка формата и имитация сверки выполняются без государственных реестров.

### C01. Сведения полны

- **Дано:** указанная карточка и соответствующий учебный документ.
- **Когда:** сотрудник вводит сведения, затем отдельно подтверждает их сверку.
- **Тогда:** валидация проходит; до сверки данные не подтверждены. После неё
  сохраняются подтверждённая версия, сотрудник, время и основание.
  Можно продолжить заявку; счёт ещё не открыт автоматически.

Связь с вводной лекцией: сотрудник вводит реквизиты и подтверждает сверку;
сервис проверяет обязательность, форматы и допустимость перехода;
сохраняются сведения клиента и отдельный факт их проверки.

### C02. Пропущен обязательный реквизит

- **Дано:** та же карточка, но номер паспорта пуст.
- **Когда:** сотрудник пытается подтвердить сведения или продолжить открытие счёта.
- **Тогда:** поле отмечено как невалидное, показана причина, подтверждение и открытие
  недоступны. Наличие других заполненных полей не заменяет номер документа.

### Дополнительные проверки карточки

| ID | Условие | Ожидаемый результат |
| --- | --- | --- |
| C03 | Дата рождения `31.02.1992` либо будущая дата | Ошибка валидации; подтверждение недоступно |
| C04 | Корректная дата отличается от учебного документа | Формат допустим, но сотрудник не подтверждает сведения до исправления |
| C05 | Отчество отсутствует | С подтверждённым основанием отсутствия допустимо; без основания требуется уточнение |
| C06 | ИНН отсутствует по условию примера / клиент не знает существующий номер | В первом случае допустимо с зафиксированным основанием; второй не трактуется автоматически как отсутствие ИНН |
| C07 | Код заполнен, название органа пусто / из формы удалён код, имеющийся в документе | Первый вариант допустим; второй требует дополнения данных, даже если название органа введено |
| C08 | После подтверждения изменена дата рождения | Новая версия требует проверки; сведения о прежней проверке доступны в истории |

## 3. Суммы, учёт и сбои

| ID | Дано и действие | Ожидаемый результат |
| --- | --- | --- |
| M01 | Учебное пополнение нового счёта на `0.01` или `999999999.99`, отдельные запуски | Допустимые границы; остаток равен сумме, проводка сбалансирована |
| M02 | Суммы `0`, `-0.01`, `1000000000.00`, `100.999`, пустое или нечисловое значение | Отказ без движения и без округления |
| M03 | Сумма `100.990` | Численно `100.99`, операция допустима при остальных выполненных условиях |
| M04 | У получателя `999999999.99`, у отправителя `1.00`; перевод `0.01` | Превышение предела получателя; оба остатка и проведённый журнал неизменны |
| M05 | У получателя `999999999.98`, у отправителя `1.00`; перевод `0.01` | Получатель `999999999.99`, отправитель `0.99` |
| L01 | Выполнены условия открытия счёта | Счёт открыт с нулём; открытие не создаёт денежного пополнения |
| L02 | Касса и клиентский счёт равны нулю; отдельное пополнение на `1000.00` | Дт кассы / Кт клиента; по обоим счетам остаток `1000.00` с учётом их типа; одна операция с автором и основанием |
| L03 | А = `1000.00`, Б = `0.00`; перевод А → Б `300.00` | Дт А / Кт Б; А = `700.00`, Б = `300.00`; одна операция и две связанные записи |
| L04 | А = `1000.00`, Б = `0.00`; перевод `1200.00` | Недостаток средств; без движения и автоматических повторов |
| L05 | То же исходное состояние; перевод `1000.00` | Успех; А = `0.00`, Б = `1000.00` |
| L06 | А = `1000.00`, Б = `0.00`; ошибка между записью дебета и кредита, откат подтверждён | А = `1000.00`, Б = `0.00`; проведённой операции нет, отдельный возврат не создаётся |
| L07 | Перевод со счёта А на тот же А | Отказ без движения |
| L08 | Два разных запроса одновременно переводят по `700.00` с А = `1000.00` на Б и В | Успешен ровно один; А = `300.00`, одному получателю зачислено `700.00`; второй отказан, отрицательного остатка нет |

Лимит остатка M04–M05 относится к клиентскому счёту. Для служебной кассы отдельно
проверяется точное суммирование нескольких пополнений, в том числе на общую сумму
более `999999999.99`; клиентский предел не обрезает её совокупный остаток.

## 4. Идемпотентность и повторы

Для R01–R04 начально А = `1000.00`, Б = `0.00`, перевод равен `300.00`.

| ID | Действие | Ожидаемый результат |
| --- | --- | --- |
| R01 | Успешная операция с ключом K, затем повтор K с теми же параметрами | Один денежный результат: А = `700.00`, Б = `300.00`; возвращены исходные ID, время и результат |
| R02 | После успеха повтор K с суммой `301.00` или другим получателем | Конфликт параметров; дополнительного движения нет |
| R03 | Два одновременных запроса K с одинаковыми параметрами | Только одна проведённая операция |
| R04 | Два намеренных перевода по `300.00` с разными ключами | Две операции; А = `400.00`, Б = `600.00` |
| R05 | Commit выполнен, ответ потерян; отправлен повтор с прежним ключом | Установлен и возвращён сохранённый успех, повторных проводок нет |
| R06 | Связь потеряна, результат commit ещё нельзя установить | Результат обозначен как неизвестный; автоматического «возврата», нового ключа или ложного окончательного отказа нет |
| R07 | Три попытки подряд завершились временным сбоем с подтверждённым откатом | Четвёртая автоматическая попытка не запускается; денежный журнал и остатки исходные |
| R08 | Первая попытка откатилась, повтор завершился успешно | Одна проведённая операция; повторены все проверки, незавершённое списание не сохранялось |
| R09 | Недостаток средств зафиксирован как окончательный отказ для K; позже счёт пополнен, повторён K | Возвращён прежний отказ; новое намерение перевести деньги требует нового ключа |

| ID | Условие | Ожидаемый результат |
| --- | --- | --- |
| A01 | Данные подтверждены, но договор или регистрация открытия не зафиксированы | Открытого счёта нет; одобрение заявки не подменяет открытие |
| A02 | Созданы два счёта; первый закрыт; создан третий | Внутренние ID и учебные номера различны, закрытый номер не переиспользован |

| A04 | Для A03 возврат `500.00` на другой открытый счёт того же клиента успешно проведён | Первый счёт закрыт с нулём; получателю зачислено `500.00`; повтор команды не дублирует возврат |

| A07 | Закрытие с нулевым остатком конкурирует с входящим переводом | Согласованный порядок: либо перевод учтён до закрытия и требуется возврат, либо перевод отклонён; закрытого счёта с ненулевым остатком нет |

| S02 | Вызов сервиса клиента, перевода или выписки без аутентификации, в том числе в обход UI | Отказ в доступе; данные не раскрываются и не изменяются |

## 6. Время и выписка

Период: **26.11.2026**, зона `Europe/Moscow`.
Интервал: `[26.11.2026 00:00, 27.11.2026 00:00)` по Москве,
или `[2026-11-25T21:00:00Z, 2026-11-26T21:00:00Z)`.
Каждая строка проверяет проведённую операцию.

| ID | Время регистрации | Попадает в выписку |
| --- | --- | --- |
| T01 | 26.11.2026 00:00 по Москве | Да |
| T02 | 26.11.2026 23:59:59.999 по Москве | Да |
| T03 | 27.11.2026 00:00 по Москве | Нет |
| T04 | 26.11.2026 21:30 UTC = 27.11.2026 00:30 по Москве | Нет, относится к следующему московскому дню |

### T05. Остатки и обороты

До начала периода остаток клиента — `1000.00`. На нижней границе проведено
пополнение `200.00`; в 23:59:59.999 по Москве — исходящий перевод `300.00`;
ровно на верхней границе — пополнение `400.00`.

Ожидается: входящий остаток `1000.00`, поступления `200.00`,
списания `300.00`, исходящий остаток `900.00`.
Текущий остаток после всех трёх операций — `1300.00`; он не подставляется
вместо исходящего остатка выписки. Результат согласован в одном снимке чтения.

### T06. Пустой период и неправильные границы

При входящем остатке `1000.00` и отсутствии операций в периоде ожидаются пустой
список операций, нулевые обороты и оба остатка `1000.00`.
Если дата начала позже даты окончания, запрос отклоняется с объяснением.

## 7. Связь с реализацией

- C01–C07: контракт и первый клиентский сценарий P0-02 / P1-02–P1-04;
  история и повторная проверка C08 — P2.
- S01–S02 и A01–A07: счета, доступ сотрудников и процесс — P3.
- M01–M05, L01–L08, R01–R09: денежная модель и проверки на PostgreSQL — P4.
- T01–T06: выборка выписки, BIRT и дальнейшая асинхронная обработка — P5.

На этапе реализации сценарии уточняются до воспроизводимых тестов с явными
точками сбоя и синхронизации. В P0-01 проверяется непротиворечивость ожиданий.
